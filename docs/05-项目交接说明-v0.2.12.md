## 3. 平台能力与不能越过的边界

| 场景 | 当前可依据的证据 | 不能宣称的事 |
| --- | --- | --- |
| 智慧树共享课视频 | `zhihuishu.py` 有登录、目录、视频与弹题路径；`test_zhihuishu_dom.py`、`test_zhihuishu_login.py` 覆盖多种离线 DOM。部分真实页面曾用于定位与有限人工测试。 | 所有智慧树课程域和所有题型已真实跑通；整门课进度已验收。 |
| 智慧树学前必读 | `prepare_page()` 有共享课和非共享课两套关闭逻辑；真实截图曾反复证明旧实现漏关，之后才修。 | 一次离线测试通过就代表每个弹窗变体都能关闭。 |
| 智慧树视频多选 | 当前按全部 DOM 选项提取，不只看首屏；有限次候选尝试，判为 `correct` 后才写入 verified 缓存。 | 仅选中部分正确选项、弹窗消失或日志写“已选中”就等于答对；当前反馈判据对所有页面变体都可靠。 |
| 智慧树平时测试/考试 | `zhihuishu_work.py` 只识别已显示的选择题，逐题页通过“下一题”前进；可检测已有答案、停止信号、保存与交卷前条件。离线 DOM 回归覆盖这些路径。 | 当前用户已提交列表就是可安全重考的题页；无真实考试题页时声称作答/服务器保存/交卷端到端通过。 |
| 超星学习通 | 视频、章节测验和独立考试有源码与离线 DOM 测试；独立考试默认填后留给人工核对。 | 视频弹题“自动试错直到正确”可靠：适配器尚缺可靠的清选、读反馈与确认关闭闭环，首次提交可能 `unknown` 后停止。 |
| 智慧职教旧版 | `icve.py` 与离线 DOM 覆盖登录、目录、视频、PPT/PDF 从首页翻阅及目录完成复核。 | 视频弹题、AI 答题、章节测验和独立考试已适配；课件走到末页就等于平台已记 100%。 |
| AI 服务商 | `test_providers.py` 验证注册表、配置与错误提示；未配置 Key 仍可按已有路径播放课程。 | 真实付费模型调用、费用、准确率已验收。 |

`answer.enabled=false` 时，`runner.py` 仍创建 `question_worker`，但 `workers.py` 的关闭分支只暂停并提醒人工，不应偷偷填题或关窗。不要用“协程仍启动”推断开关失效，也不要只用 `hasattr()` 判断平台弹题能力；要测具体子类行为与副作用。视频弹题重试会提交尝试；独立测试和考试不做换答案试错。

正式考试默认只允许填写并保留页面供人工检查。即使代码提供自动交卷开关，维护者也不得在真实考试上点交卷，除非用户针对可安全测试场景再次明确授权。验证码和滑块由人手动处理，不实现破解。

## 4. 我犯过的错误：修正方法与下一次的判据

以下是本项目迭代中我已被用户反例纠正过的判断或实现失误。列出它们是为了让接手者先检查证据，而不是继承我的自信。

1. **把“代码路径存在”当成“真实可用”。** 早期描述容易把离线 DOM、EXE 能启动、ZIP 能解压混成真实验收。修正：每一结论标明证据层级；真实课程要看进度、平台反馈和最终回执，不能只看本地日志。README 中较乐观的概述也必须由代码和现时页面重新核对。
2. **凭单套页面选择器处理所有智慧树页。** 旧版“学前必读”弹窗在另一套课程页面反复漏关；一次声称修好后，用户的下一张截图仍显示遮挡。修正：先辨认课程域和弹窗容器，取得授权的脱敏 DOM/截图，在对应容器内定位关闭钮，并验证遮罩真正隐藏；回归覆盖至少两套页面。不把用户重复反馈解释成“缓存问题”而跳过取证。
3. **多选题局部正确误判整题正确。** 仅看到选项上的正确样式或弹窗关闭，会把少选的组合当作通过；还有选项在弹窗滚动区下方，不能凭截图可见的前四项推断总数。当前已改为读取全部选项、优先检查题目级判错、共享课弹窗消失不直接算正确；`unknown` 不写 verified 缓存。**剩余风险：**`read_feedback()` 仍有选项级 `right` 样式回退，遇到新页面若它仅表示局部正确，仍可能误判整题；必须用授权真实 DOM 核对后才能宣称修完。对应 `test_zhihuishu_dom.py`、`test_retry.py`。
4. **弹题未结束就去核对课程目录。** 主循环可能在题目弹窗占据页面时读取不到目录，报“目录核对失败”并停止。修正：切章节前等待视频弹题处理结束，平时测试占页时区分 `work_page`，返回目录后再复核。见 `runner.py`、`zhihuishu.py` 的相关守卫与离线回归。
5. **停止按钮只在外层检查。** 逐题处理、等待模型或平台页面保存时，用户点停止曾不能及时打断。修正：在导航、每题、异步模型等待和提交前检查 `should_stop()`；不要在正式交卷动作后才检查。见 `zhihuishu_work.py`、`test_login_stop.py` 与 `test_zhihuishu_dom.py`。
6. **首启字体和图标只看第二次启动。** 首次无配置和配置损坏路径的 Tk 字体/DPI 初始化顺序曾与重开不同；标题栏、任务栏、Alt-Tab 还可能显示不同图标。修正：先设置 DPI/图标/默认字号再建控件；打包后只在不含个人数据的新副本中连续启动两次并截图。`test_gui_dpi.py`、`test_first_launch_visual.py` 只覆盖代码和截图条件，任务栏与 Alt-Tab 仍要人眼复核。
7. **把源码依赖脚本当成 EXE 修复工具。** 打包 EXE 缺模块时运行 `安装依赖.bat` 只会改系统 Python，不能补 PyInstaller 的 `_internal`。修正：发布包可保留脚本和清单，但明确“仅供源码运行”；EXE 缺依赖必须重打完整包，并重新做首启视觉验收。
8. **发布说明写得过细，泄露用户测试轨迹。** 具体课程章节、时间点、截图文字和课程地址虽非密码，也属于个人学习记录。修正：公开文字只写平台级能力和泛化问题；提交/Release/ZIP 逐文件核对。不把本机日志、截图、课程地址或历史提交内容复制进文档。
9. **以为重写 Git 历史就等于外部缓存清空。** 即使得到授权并改写公开历史，旧提交对象与网页缓存可能暂时仍可访问。修正：区分仓库当前树、所有 refs、Release 附件和托管站缓存；需要平台清理时单独处理并复查，不能宣布“隐私已彻底消失”。
10. **按目录/文件名清理旧包容易碰到个人数据。** 运行过的 `dist/` 副本可能生成配置与 runtime。修正：删除前列精确清单逐项确认；打包永远用新的专属 `--distpath`/`--workpath`；未获授权不删除或覆盖。运行过的目录不再压缩发布。

## 5. 安全边界与隐私检查

- `.gitignore` 排除 `config.toml`、`runtime/`、`*.log`、`dist/`、`build/`、`*.lnk` 等；**忽略规则不代替审查**。提交前看 `git status --short`、`git diff --cached --name-only` 和暂存区内容，不用 `git add -f`。
- Cookie、SQLite 题库、日志、截图、模型密钥、课程地址、账号、密码、快捷方式目标和已运行过的发布副本均为本机数据；不要写入代码、文档、聊天回复、Git、ZIP 或 Release。需要故障样本时，先脱敏再使用，原始日志留在本机。
- `runner.py` 的某些错误日志可能含 URL，平台页面可能含课程或题目文本；发给他人之前必须审阅并脱敏。自动测试截图也可能截到桌面其他窗口，绝不直接上传。
- 首次启动测试工具只从干净发布目录复制 `CourseMate.exe` 与 `_internal/`，不复制配置/runtime，并会检查副本是否生成非空个人字段。原始待发布目录保持不运行；测试副本不得重新打 ZIP。
- 旧文件删除、真实课程推进、正式考试、付费模型调用、GitHub 提交/推送/Release 都要按**本次任务**重新确认范围。旧对话中的一次性授权不是永久授权。

## 6. 下一位维护者的最小工作流程

1. **核对边界**：先读本文件、`README.md`、用户当次指令、`AGENTS.md`（若存在）；运行 `git status --short`，标明现有改动；检查版本、HEAD、标签和要碰的模块。若有多种解释，列出并说明采用哪一种。
2. **复现问题**：从日志摘要与用户授权的脱敏 DOM/截图定位页面变体；优先写最小离线回归，再只改直接相关代码。不能凭旧课程地址猜新选择器；不能用 `hasattr()` 当子类能力证据。
3. **执行验证**：Windows PowerShell 先设 `$env:PYTHONUTF8 = '1'`，再运行 `python -m compileall -q coursemate` 和相关 `python tests/test_*.py`；跨模块改动时枚举全套。保留任何失败输出并定位，不跳过失败项。
4. **真实页面**：只有用户对具体安全测试场景授权后才打开课程；不碰正式考试交卷。检查“页面点击/选中”“平台明确判对”“目录完成状态”“服务器回执”四种不同证据，不要互相替代。
5. **打包和发布**：仅在用户明确要求时执行。新版本同步 `coursemate/__init__.py`、README 和发布说明，用从未存在过的 `dist/<本次版本>/`、`build/<本次版本>/`；`build.py` 会在隔离副本截图，但任务栏/Alt-Tab 需人工目视。检查 ZIP 内容无个人数据，发布源目录不得运行；如需改快捷方式，只指向本次已验收 EXE。提交、标签、推送和 Release 分别核实后再报告。

全套离线/本机代码回归的 PowerShell 示例（不触发真实课程）：

```powershell
$env:PYTHONUTF8 = '1'
git status --short
python -m compileall -q coursemate
$failed = @()
Get-ChildItem tests -Filter 'test_*.py' | Sort-Object Name | ForEach-Object {
    python $_.FullName
    if ($LASTEXITCODE -ne 0) { $failed += $_.Name }
}
$failed
```

`test_packaging.py` 的 `[SKIP]` 必须单列；不能因为整套命令退出码为 0，就把打包测试或视觉验收写成通过。需要打包时，按 `build.py --help` 使用新目录，并在发布前人工审阅 `tools/first_launch_visual.py` 产生的首启/重启截图与任务栏、Alt-Tab 图标。

## 7. 交接完成时怎样汇报

按以下固定顺序写事实，不用“应该没问题”一类判断：

1. 改了哪些文件和行为，为什么。
2. 代码/离线 DOM 测试：命令、通过数、失败与跳过。
3. 本机 EXE：是否新打包、是否在隔离副本两次启动。
4. 首启视觉：三页字体、标题栏/任务栏/Alt-Tab 图标是否**实际目视**一致；截图存于本机哪个忽略目录。
5. 真实网页：哪类流程得到授权并真实核对；未看到服务器回执则明确写未验收。
6. 隐私与发布：暂存区、ZIP 和 Release 资产是否审查；是否提交/推送/发布/更新快捷方式/删除旧包。

最重要的习惯：**用户的一张反例截图优先级高于十条模拟测试的“通过”**。先承认反例、收集该页证据、收缩结论，再修对应行为。
